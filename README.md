# Glass Notes

中文 · [English](README.en.md)

从今天想喝什么，到记住自己喜欢什么。Glass Notes 是一款专注个人体验的鸡尾酒工具：按口味选酒，用手边材料调酒，保存自己的配方、酒单和风味笔记。

**367 款鸡尾酒 · 371 个来源版本 · 1,042 款瓶装酒 · 8 种界面语言**

## 功能介绍

### 按心情选一杯，或用已有材料自己调

从首页进入“为我定制”，先选一种模式，再回答香气、口感、酒感和第一口的偏好。可以多选或跳过，也可以加入场合、季节条件，以及自己保存的口味记忆。

选择会在右侧的酒杯中留下可见的变化：柑橘、果味、花香、草本、香料和咖啡带来不同装饰与酒液颜色；口感、酒感和第一口改变持续的波纹与液体运动。这些是风味的视觉表达，不代表实际配方或测得的酒精度。

| 喝一杯 | 自己调 |
| --- | --- |
| 从口味出发寻找合适的酒。 | 根据酒柜里已有的材料和瓶款推荐配方。 |
| 查看推荐理由，再进入具体配方。 | **先基酒齐全，同组再按缺料数量排序**；排除缺少 3 种及以上材料的配方，并列出缺项。 |

酒柜为空时，可以先添加材料，也可以直接按口味选酒。制作前请查看配方，确认用量、器具及需要提前准备的材料。

![香气选择实际页面：花香选项与淡紫色酒液、花朵装饰联动](docs/images/flavours-zh.png)

点击“找一杯适合我的”，文字淡出，酒杯移到中央旋转，再由推荐结果接替。可以直接跳过动效查看结果。推荐保留具体来源版本及匹配理由；展示区域根据结果数量安排单杯、双杯或多列布局。

### 看着图片逛酒单，找到确切配方

“随便逛逛”支持名称、别名和材料检索，以及基酒、材料包含与排除、风味、手法和无酒精条件。也可以按经典鸡尾酒、竞赛作品、知名酒吧配方浏览，结合场合与季节缩小选择。

每款酒用一张卡片展示，详情中可以切换不同来源的配方。筛选会找到同时满足所选条件的版本，点击卡片即可查看。

保存明确的口味评价后，“随便逛逛”会用本地统计模型挑选最多五杯合口味的酒，再推荐一杯符合当前条件、你尚未记录的酒。可以展开简短理由，或只换最后一杯。文字搜索继续按查询条件浏览酒库。

![当前中文酒库，包含酒款图片、配方入口与收藏操作](docs/images/discover-zh.png)

配方详情提供材料与用量、制作步骤、杯型、装饰、预制说明和风味提示。可以对照原文阅读步骤，也可以打开配方出处和图片来源。

![内格罗尼详情，包含确切来源版本与调制、点单、收藏、口味入口](docs/images/recipe-zh.png)

### 酒柜、材料库与瓶款档案

在酒柜中标记已有的材料和瓶款，“自己调”就能据此推荐配方。

酒柜的“补货规划”比较补一种或两种材料后能新增哪些酒，并标明需要两项一起补的酒款。可按“解锁更多”或“更合口味”排序，再展开核对确切来源版本、品牌和预制材料。规划按材料是否拥有计算，调制前仍需核对余量和器具。

“购物单”按选定的具体配方版本合并必需缺料，替代材料只选一种。配方详情页可直接将当前版本加入购物单；在酒柜查看、修改或移除购物项，确认购入后加入酒柜。购物单保存在本机并纳入完整备份；旧备份没有购物单时会保留本机清单。购入只记录材料拥有，不填写价格或余量。

材料库按日常使用展示主项：纯基酒风格归到同一品类，果味、浸泡与预制材料独立保留。普通盐水只有一个入口，浓度和原用量在具体配方内说明。旧材料名称仍能搜索，已有瓶款与记录继续保留。

材料库帮助查看材料及相关配方；瓶款档案支持名称、品牌、别名和风味描述搜索，以及品类筛选。可查看瓶图、酒精度与产品说明，标记拥有，或选择瓶款进行比较。

![当前瓶款档案，包含品类筛选、产品图片与资料](docs/images/bottles-zh.png)

### 跟着配方调制，或出示一张点单卡

点击“开始调制”，按顺序查看材料、步骤和制作提示。进度会自动保存，做完后可以再调一杯或返回酒单。

首批 20 个已审阅的 IBA 版本提供有来源的酒精度参考及长饮或短饮分类。展开酒度参考可查看用量、瓶款依据和已知限制，或输入融水量比较稀释前后。所选材料或剂量资料不足时会列出缺项。

点单卡把酒名、材料和明确的个人要求放在简洁卡片中，可选择应用语言或来源语言、出示卡片、复制文字，或在平台支持时分享文字。私人风味笔记不会混入点单内容。

![实际出示的中文点单卡，展示酒名、原名与材料](docs/images/order-zh.png)

### 我的收藏、私人酒单与口味记忆

喜欢一个配方可以直接收藏；想为周末、聚会或试饮整理一组酒，可以创建私人酒单。“添加酒款”进入同一套图片酒库，选好具体版本后加入。

酒单保留添加时的确切配方快照，可以分别查看保存的配方和酒库中的当前配方。卡片显示酒图，同款酒的不同来源版本归在一起。

在配方中选择“记录口味”，直接打开“酒名的风味体验”。可以记录喝过或调过、喜欢或不喜欢、是否太甜或太烈、喜欢的香气，以及私人笔记。

明确保存的评价用于“随便逛逛”的精选与“更合口味”的补货排序。“为我定制”以本次回答为主，口味记忆可手动开启。

![当前风味体验页面，记录饮用经历、明确评价与口味调整](docs/images/taste-zh.png)

### 我的配方：写下来，也留下自己的照片

可以从空白创建配方，也可以从酒库的确切版本或实验室复制一份再调整。材料、用量、步骤、杯型、装饰和笔记由自己编辑，保存修改会保留历史版本。

为自己的配方选一张照片，和材料、步骤、笔记一起保存。导出备份时，照片也会一并保留。

### 专业区：专题研究与我的实验室

| 工具 | 可以做什么 |
| --- | --- |
| 专题研究 | 按国家、赛事与酒吧浏览。新增 12 份 Patrón Perfectionists 与 Angostura Global Cocktail Challenge 公开作品的用量、方法和预制资料，可打开主办方原始出处。 |
| 瓶款比较 | 并排比较产品资料，从空白或已有配方建立不同瓶款的对照项目。 |
| 配方版本 | 建立项目、编辑用量与手法、复制为下一版，并比较版本差异。 |
| 试调批次 | 保留当次配方快照，记录时间、温度、香气、口感、外观、结果和下一步。 |
| 结果对照 | 比较实际批次，从选定快照继续建立命名版本，或存为“我的配方”。 |

实验室记录自动保存到本地，方便下次试调时接着修改。

### 八种语言与跨屏体验

支持中文、English、Français、Deutsch、Español、한국어、日本語、Italiano。首次使用参考设备语言，也可在工具栏切换。酒款和瓶款名称随所选语言显示，下方保留不同的原名，方便对照查找。

电脑与手机网页均可使用全部功能。液体用量支持 ml / fl oz 切换，其他计量保留原单位。

界面以深绿、象牙白、大字标题和细分隔线贯穿首页、选酒与个人记录。首页每次新访问从酒库抽取三杯不同的酒，可以直接打开配方；调整窗口或切换语言不会更换这组三杯。酒图从列表衔接到配方页，风味选择与酒杯保持联动。

手机页面为酒杯保留独立的内容区域，随页面一起滚动；首页酒图、偏好标题和选择按钮按内容顺序排布，避免模型覆盖文字或入口。

动效可以暂停，并遵循系统的“减少动态效果”偏好；页面进入后台或模型离屏时停止持续运动。README 截图取自实际应用，部分界面在新版中已有调整。

## 本地数据与备份

收藏、酒单、酒柜、私人配方、实验、调制记录、口味记忆及偏好保存在当前浏览器或应用中，不会自动同步到其他设备。

换设备时，在“我的 → 备份与恢复”导出 JSON 文件，再到新设备导入。检查恢复预览中的分类和冲突后，选择合并或替换。

请注意：

- 不同浏览器配置、网页来源（协议、域名或端口）和设备拥有各自的数据；同一系统用户下的桌面应用副本与升级版本共用固定的应用数据目录。
- 清除站点数据、无痕会话结束或卸载可能丢失记录。迁移前先导出备份。
- 备份包含私人笔记和照片，**没有加密**，请妥善保管，避免公开分享。
- “替换”可能移除所选分类中的现有记录；先查看恢复预览并保存旧备份。
- 网页版加载页面和资源需要网络。

## 开始使用

网页版无需安装。Windows 用户下载 `windows-x64-setup.exe` 后运行安装程序；macOS 12 及以上用户下载 `macos-universal.dmg`，打开后将 Glass Notes 拖入 Applications，同时支持 Apple Silicon 和 Intel。升级前请先导出个人数据备份，并退出旧版本。

macOS 版使用 ad-hoc 签名，首次打开可能需要在系统设置的「隐私与安全性」中选择「仍要打开」。Windows 安装包未签名。可在 Release 核对 SHA256，更新时下载新版安装包覆盖安装。

### 从源码运行

需要 Node.js 24 和 npm：

```sh
git clone https://github.com/AlexShen-Oguri/glass-note.git
cd glass-note
npm ci
npm run web
```

若要运行与静态部署相同的导出：

```sh
npm run build:web
npm run preview
```

打开 http://127.0.0.1:4173。源码变化后重新构建；预览服务仅用于本地测试。

## 开发与构建

项目使用 Expo / React Native / TypeScript，共享业务规则与界面；手机使用以网页为主，Windows 和 macOS 使用 Tauri 2 加载静态 Web 导出。Web 与桌面使用 Three.js 酒杯模型及 GSAP 转场；手机通过浏览器使用，原生手机开发工具及 iOS 导出已移除。运行时不需要应用后端、数据库或模型 API 密钥，字体与产品资料随应用打包。

```sh
npm run browser:install
npm run validate
npm run brand:check
```

首次验证先安装锁定的 Chromium。`validate` 包含类型检查、行为与内容测试、Web 导出及桌面/手机宽度浏览器 E2E。手机交付另按真实手机浏览器验收。

Windows x64 构建：

```sh
npm run desktop:prepare
npm run desktop:test
npm run desktop:build
```

需要 Rust MSVC 工具链、Visual Studio C++ 构建工具和 Windows SDK。安装包面向当前用户；安装后运行依赖 WebView2，不要求使用者安装 Node.js 或 Expo。

macOS 通用安装包构建（需要 Rust 和 Xcode Command Line Tools）：

```sh
rustup target add aarch64-apple-darwin x86_64-apple-darwin
npm run desktop:test
npm run desktop:build -- --target universal-apple-darwin
```

`.github/workflows/desktop-release.yml` 在版本标签推送或手动触发时分别使用 Windows、macOS runner 构建，默认检查从 Windows 1.0.0 升级的样例文件保留，以及 macOS 双架构和签名。构建产物通过检查后再发布到 GitHub Release；Linux 尚未打包。

覆盖安装和个人记录保留按 [Windows/macOS 升级验收指南](docs/DESKTOP-ACCEPTANCE.md) 操作；其中说明现有 CI 的样例文件检查与实际业务验收的区别。

独立网站打包：

```sh
npm run release:web
```

在 `release/` 生成静态网站归档、文件校验信息及 Caddy 配置示例。将其中的 `site/` 内容部署到静态托管服务即可。

| 目录 | 内容 |
| --- | --- |
| `src/app`、`src/features` | 路由与界面 |
| `src/domain` | 搜索、推荐、快照、计算与校验 |
| `src/content`、`src/media`、`assets` | 酒库、瓶款、材料、多语言资料与图片 |
| `src/platform` | 本地存储、文件选择、恢复和平台适配 |
| `src-tauri` | Windows / macOS 宿主与受限文件桥接 |
| `scripts`、`deploy` | 测试、构建、打包与自托管示例 |
| `research` | 内容维护与回归证据；[目录说明](research/README.md)，运行时不加载 |

品牌统一维护于 `assets/brand`；Web/桌面图标由入口自动生成，设计预览和生成报告不提交。目录取内容名称；保存数据的历史 ID 保持稳定。

详见[架构说明](docs/ARCHITECTURE.md)、[自托管指南](docs/HOSTING.md)和[贡献指南](CONTRIBUTING.md)。
